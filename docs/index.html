Muybridge

Take still frames out of video, at whatever rate you ask for.

Point it at a file, say how often to sample, and it writes a numbered sequence of frames into the folder you choose. Long videos are trimmed by eye on a filmstrip — not by typing timecodes at them.

See it

A GNOME-native window, driven entirely by the bundled ffmpeg. Click any shot to enlarge.

Pick the range by eye — a filmstrip of the whole video, with the frame under the handle above it. Drag the ends to trim. Everything outside the selection dims. Rate, format and naming — with the first filename and frame count shown before anything runs. Live progress while ffmpeg works, and a cancel that keeps what it already wrote. A finished run says how many frames it wrote, and where.

Why Muybridge?

Because the ffmpeg command that does this is easy to write and easy to get wrong — a mistyped timecode, a % in a filename, a range that runs backwards, an overwrite prompt nobody sees.

Features

A filmstrip, not a timecode box

Twelve thumbnails across the video with draggable start and end handles, and a larger preview of the frame under whichever one you moved last.

The preview is the output

Frames are previewed by the same bundled ffmpeg that writes them, seeking the same way. What you picked is what you get.

Arrow keys that mean something

Put the cursor on the minutes and press Up. Page Up steps by ten. Precise enough for a two-hour video without typing a single timecode.

Know the job before it runs

The first filename and a frame estimate update live as you change the settings — so a job that would write 40,000 files says so first.

Drop it, or open it

Drag a video onto the window, or open one straight from Files. A dropped folder becomes the output folder.

Sandboxed by default

No host filesystem access and no network — not even for ffmpeg, which is built with networking disabled. Files arrive through the desktop portals.

Nothing hidden

The app builds exactly one kind of command line, and its tests assert it argument for argument. This is it:

ffmpeg -hide_banner -nostdin -y \
       -ss 00:17:11.448 -to 00:38:54.374 \
       -i INPUT.mp4 \
       -vf fps=3.33 \
       -progress pipe:1 -nostats \
       OUTDIR/NAME_%04d.png

-ss and -to sit before -i so ffmpeg seeks the input instead of decoding and discarding everything up to the start. Overwrite is always stated explicitly, because the interactive prompt would hang a GUI forever. Commands are spawned as an argument vector, never as a shell string — a filename with a space or a $ in it is just a filename.

Roadmap

  • Extraction — trim range, PNG/JPEG, frame estimate, live progress, cancel
  • Pick the range by eye — filmstrip, scrub preview, arrow-key timecode stepping
  • More output formats — AVIF, WebP and TIFF. AVIF is roughly a tenth of PNG's size for a few minutes of CPU on a long job
  • Scale — an optional output size, so frames come out ready to use
  • “Every N seconds” — an alternative to frames-per-second, since that is often how the job is actually described
  • Batch — a queue of videos sharing one set of settings

Muybridge extracts frames and will not grow into a video editor — anything that writes video belongs to a different tool.
